# VideoFlow 路线图

## V0.1：本地媒体转录

- [x] T00 项目初始化与开发规范
- [x] T01 语音识别核心（已完成真实媒体转录验收）
- [x] T02 Gradio 界面与字幕导出（已完成真实结果与 TXT/SRT 验收）
- [~] T03 稳定性测试与问题修复（自动化和一份真实输入已通过；更多边界输入仍可后续补充）
- [x] T04 GitHub 发布准备（文档、许可证、忽略规则、演示说明和公开远程仓库已就绪；未创建 Git 标签或 GitHub Release）

V0.1 范围：本地音视频转录、时间戳、结果预览、UTF-8 TXT 与 SRT 导出。默认 CPU INT8，支持自动或手动语言指定。

## V0.2：B 站已有字幕导入

- [x] T00 可行性验证：yt-dlp 可仅请求字幕；公开样本无登录时被平台要求登录，已作为产品边界处理。
- [x] T01 字幕来源适配器：严格校验单 BV 链接、仅下载 BCC 字幕 JSON、统一为 `Transcript`。
- [x] T02 双模式界面：保留本地转录，新增 B 站链接导入与可选本机浏览器会话。
- [x] T03 测试与回归：16 项离线自动化测试通过；无登录真实请求返回受控错误。
- [x] T04 文档与版本交接：完成 README、状态、发布说明和 v0.2 交接报告。

V0.2 只导入用户可访问的 B 站已有字幕，不下载视频。课程平台登录、Cookie 管理、批量链接与其他网站链接不在本版范围。

## V0.3：在线播放声音本地转写与错误可见性

- [x] T00 课程回放合规方案：不提取受保护视频流，改为用户正常播放时的本机扬声器回环录音。
- [x] T01 Windows 音频适配：使用 WASAPI 回环设备录制默认扬声器，停止后复用既有本地转录和导出链路。
- [x] T02 交互与隐私：增加用户权限确认、开始/停止控制和临时 WAV 删除；不读取 LMS 链接、账号或 Cookie。
- [x] T03 B 站可诊断错误：将回调异常显示为具体状态文本，避免页面只显示“错误”。
- [x] T04 自动化测试与文档：增加回环录音生命周期、权限确认和 B 站错误展示的离线测试。

V0.3 不能下载、解密或绕过任何课程回放；它只记录用户在本机正常播放时的电脑声音。实际课程录音效果仍需在目标 Windows 音频设备上验收。

## V0.4：在线音频快速转录与批量任务

- [x] T00 B 站独立音频：使用 yt-dlp `bestaudio` 获取临时音频，不回退下载完整视频。
- [x] T01 批量处理：单次接受最多 10 个 BV 链接，逐项隔离失败并将每个 TXT/SRT 打包为 ZIP。
- [x] T02 转录性能：缓存最近使用的 Whisper 模型，批量任务不再为每个视频重复加载模型，并串行保护模型推理。
- [x] T03 LMS 短期任务：提供权限范围仅为西交 LMS 的本地浏览器扩展，用户点击后复制单个活动的播放器任务；Python 端换取当前账号已获准访问的最佳音频回放流。
- [x] T04 安全与清理：不存储 Cookie/token/签名 URL，不在错误中打印敏感数据，临时音频转录后删除，拒绝非 HTTPS、私有网络和 DRM 失败路径。
- [~] T05 真实验收：B 站独立音频端到端成功；LMS 需要用户在自己的已登录课程页面完成一次真实验收。

V0.4 的优先顺序是“已有字幕 → 独立音频/已授权课程流 → 扬声器实时录音兜底”。批量转录按队列顺序执行，避免多个 CPU Whisper 任务同时争用内存。

## V0.4.1：LMS 兼容性、转录性能与界面整理

- [x] T00 LMS 403 修复：优先使用 `download_url`，为 FFmpeg 添加 LMS `Origin`/`Referer`，并按主音源、备用地址和其他机位依次重试。
- [x] T01 可诊断错误：区分 401、403、404、无音轨和媒体清单失败，不回显带签名地址。
- [x] T02 性能与准确度：增加快速、均衡、高精度预设，使用 faster-whisper 批量推理，并支持课程关键词提示。
- [x] T03 页面整理：顶层入口收敛为本地文件、在线内容和兼容录音；B 站已有字幕、B 站音频与 LMS 在在线内容中分组。
- [~] T04 LMS 复验：已根据用户真实失败定位并修复 403 根因；仍需用户使用同一课程短期任务确认平台端到端成功。

## V0.4.2：转录质量与长视频稳定性维护

- [x] T00 长视频诊断：确认没有固定 30 分钟限制；定位整段批量特征的内存风险和页面缺乏真实进度，形成 `docs/TRANSCRIPTION_DIAGNOSIS.md`。
- [x] T01 稳定性修复：20 分钟以上使用 5 分钟重叠分块、块内批量识别，记录媒体时长、最后字幕位置、耗时、RTF、CPU 时间和峰值内存；可疑尾部不标记为完整成功。
- [x] T02 TXT 排版：与字幕分段解耦，保留已有标点和中英数字内容，在可靠自然边界分段；所有 TXT/ZIP 路径统一生效。
- [~] T03 质量/速度基准：已提供 CER/RTF/内存工具并完成 tiny 实测；缺少人工参考稿，small、SenseVoiceSmall 和 Paraformer 尚未公平比较。
- [x] T04 已验证优化：CPU 模型显式使用最多 8 线程；保留短媒体批量速度，长媒体使用有界内存的分块批量路径；未增加未经证明收益的大型依赖。
- [x] T04a 中文质量修复：快速档由 tiny 改为 base/beam 1，增加解码重复抑制，并用本地 OpenCC 保证简体中文输出；不把后处理描述为准确率提升。
- [x] T04b GPU 质量增强：RTX 设备可选多语言 turbo/beam 5/FP16；Windows CUDA 依赖保持可选，术语提示改用 hotwords，避免 initial prompt 污染正文。
- [~] T05 回归与交接：59 项自动化通过；65 分钟稀疏样本和 60 分钟连续有声重复样本均到达末尾；真实 60–90 分钟课程及 LMS 登录态仍待用户验收。

V0.4.2 不新增平台、摘要、翻译或知识库。准确率改进必须以人工参考稿 CER 为准，不能用字符数代替。

## V0.4.3：GPU 自适应与可疑片段精修

- [x] T00 GPU 可观测性：记录本进程峰值显存、GPU 名称和实际批量大小；无 NVIDIA 工具时安全降级为“未测”。
- [x] T01 吞吐稳定性：RTX 总显存达到 8 GB 时优先尝试批量 8；出现 CUDA 内存不足时对当前音频/分块自动逐级回退，不重试整段课程。
- [x] T02 质量辅助：根据模型的平均对数概率、重复率和无语音概率标记需复核分段；提供最多 12 段的可选高 beam 二次识别，只在模型自身分数更高时采用候选。
- [x] T03 术语整理与基准：热词按常见分隔符去重、清理空白并限制数量；基准表新增显存、实际批量和需复核段数量。
- [~] T04 中文替代引擎：FunASR/SenseVoice/Paraformer 仅作为隔离实验候选，必须先在同一人工参考稿上比较 CER、时间戳质量、速度和许可证，未替换默认 faster-whisper。

V0.4.3 不把模型启发式分数、可疑标记或二次尝试描述为 CER 提升；默认路径仍是已验证的 faster-whisper GPU turbo/CPU base。
