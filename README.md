# VideoFlow

VideoFlow 是一个优先本地运行的视频/音频转文字工具。V0.4.3 提供本地媒体转录、B 站已有字幕导入、B 站独立音频批量转录、西交 LMS 已授权课程回放快速转录，以及播放中的电脑声音录制兜底；结果可带时间戳预览并导出适合阅读的 UTF-8 TXT、标准 SRT 字幕。

它面向希望快速获取视频内容的个人用户，也为后续学习整理、课程内容提取等能力保留扩展空间。不会上传媒体到服务器，也不会默认开启公网分享。

## 功能

- 使用 `faster-whisper` 转录本地音频和常见视频文件
- 导入 B 站单个 BV 视频中当前账号可访问的已有字幕；不会下载完整视频
- 从最多 10 个 B 站 BV 链接提取独立音频后批量转录；无需播放，不受电脑其他声音干扰
- 通过权限受限的本地浏览器助手转录当前账号可以播放的西交 LMS 回放
- 默认 CPU `int8`；快速档使用 base/beam 1，均衡档使用 base/beam 5，高精度档使用 small；NVIDIA 显卡可选 turbo/FP16 增强档
- 可填写课程关键词、人名或术语，通过专用 hotwords 提示改善专有词识别
- 中文转录统一使用 OpenCC 离线转换为简体，并压缩明显的连续重复幻觉
- 自动识别语言，也可指定中文、英文、日文或韩文
- 网页中查看每段开始/结束时间与文字
- 导出自然段排版的 UTF-8 TXT 和保持时间轴分段的标准 SRT
- 显示媒体时长、最后字幕位置、推理耗时、RTF、峰值内存和覆盖检查
- GPU 模式显示当前 Python 进程的峰值显存与实际批量；8 GB 显存会优先尝试批量 8，显存不足时自动回退
- 标记模型提示为低置信、疑似重复或可能无语音的字幕段；可选只精修最多 12 个可疑片段，不重跑整段课程
- 命令行入口，便于排查和自动化使用

## 安装

需要 Python 3.11–3.13 和已安装的 [FFmpeg](https://ffmpeg.org/)（本机已经能在命令行执行 `ffmpeg -version`）。首次转录会下载所选 Whisper 模型；模型大小和耗时随模型选择及机器性能变化。

```powershell
git clone <你的 GitHub 仓库地址>
cd VideoFlow
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

本机有兼容的 NVIDIA 显卡时，可额外安装约 1 GB 的官方 CUDA 运行库：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,gpu]"
```

GPU 依赖是可选项，没有 NVIDIA 显卡时不需要安装。Windows GPU 额外依赖采用 NVIDIA 官方 `nvidia-cublas-cu12` 与 `nvidia-cudnn-cu12` Python 包；VideoFlow 会在启动时检测完整运行库，检测失败时隐藏 GPU 增强档。

## 使用

启动本地网页：

```powershell
.\.venv\Scripts\python.exe app.py
```

浏览器打开终端显示的本机地址（默认是 <http://127.0.0.1:7860>）。界面只在本机访问，不会设置 `share=True`。

这里不要求先执行 `Activate.ps1`；直接调用虚拟环境里的 `python.exe` 更稳定。如果当前窗口已经运行了 `python app.py`，请先按 `Ctrl+C` 停止，再使用上面的命令。

页面顶部的“转录设置”由所有语音识别入口共用：检测到完整 NVIDIA CUDA 环境时，默认选择“GPU 增强 + 中文”，使用多语言 turbo/beam 5；没有兼容显卡时默认“均衡 + 中文”。快速档仍使用 base/beam 1。“课程术语热词”只填写确实会在音频中出现的教师姓名、专业术语及英文缩写，使用逗号、分号或换行分隔；程序会去重并通过 faster-whisper 的专用 `hotwords` 参数传递，不再把术语当作上一段正文。20 分钟以上的媒体会自动按 5 分钟分块、块内批量识别，进度条显示当前块和已处理的媒体位置。

GPU 增强会根据显存容量选择批量大小：本机 8 GB 显存默认先试批量 8，显存不足时只对当前媒体或分块回退到 4、2、1。可通过 `VIDEOFLOW_GPU_BATCH_SIZE=1..8` 固定批量，便于复现基准。诊断中的显存只统计 VideoFlow 当前 Python 进程；某些驱动不提供该统计时显示为未测。

“精修可疑片段”默认关闭。勾选后，程序最多用更高 beam 重试 12 个模型提示为低置信、疑似重复或可能无语音的片段，只有候选的模型内部评分更高才采用。它能控制额外耗时，但不是人工参考稿 CER，仍应抽查“复核提示”列。

### 推荐操作顺序

1. **先重新启动程序。** 更新代码后，旧网页进程不会自动加载新逻辑；在运行 `app.py` 的 PowerShell 中按 `Ctrl+C`，再执行 `.\.venv\Scripts\python.exe app.py`。
2. **先选最快的来源。** B 站先试“已有字幕”；没有字幕再用“B 站音频”。西交课程优先使用浏览器助手。只有直连失败时才用“兼容录音”。
3. **优先使用 GPU 增强。** 本机页面检测到 RTX/CUDA 后会默认选择该档；语言明确为中文时直接选“中文”。课程热词用逗号分隔填写术语、人名和英文缩写。
4. **完成后看状态行。** `RTF 0.1` 表示处理时间约为媒体时长的 10%；`RTF 1.0` 才是接近实时。确认“媒体时长”与原视频一致，并检查“最后字幕”是否接近最后一段实际讲话的位置。
5. **抽查后再决定是否重跑。** GPU 增强仍有术语错误时，先补充准确的课程热词再重跑代表片段；不要把整段说明或错误转录粘进热词框。TXT 适合阅读，SRT 适合播放器加载。

不要同时打开两个 VideoFlow 服务或并行启动多个 Whisper 转录。CPU 会互相争用，反而更慢。转录时接通电源、关闭系统节能模式，并避免电脑进入睡眠。关闭浏览器标签不会可靠地取消后台任务；需要取消时回到启动程序的 PowerShell 按 `Ctrl+C`，然后重新启动。

### 本地文件转录

选择“本地文件”，上传媒体并点击“开始转录本地文件”，然后下载 TXT 或 SRT。

### B 站链接导入已有字幕

1. 选择“在线内容 → B 站 → 已有字幕”。
2. 粘贴完整单视频 BV 链接，例如 `https://www.bilibili.com/video/BV1.../`；短链、合集和空间页不支持。
3. 选择字幕语言。若未登录也能访问字幕，保持“不使用登录”即可。
4. 若 B 站提示字幕需要登录，在下拉框中**主动选择**已登录 B 站的 Chrome 或 Edge，点击“导入已有字幕”。VideoFlow 只让 yt-dlp 临时读取本机浏览器会话，不保存、显示、上传或提交 Cookie。
5. 查看时间戳结果，下载 TXT 或 SRT。

该模式只获取平台已有字幕 JSON，不下载完整视频，也不会绕过登录、付费或 DRM 限制。

“**仅公开可访问字幕**”不是指“视频页面公开”或“所有人都能看到视频”，而是指：在**不读取 Chrome/Edge 登录会话**的情况下，B 站仍允许程序取得该视频现成的文字字幕轨。公开视频的字幕接口也可能要求登录，因此公开可播放的视频不一定有“公开可访问字幕”。如果失败，可以明确选择已经登录 B 站的浏览器；若视频本来就没有字幕轨，则应使用“没有字幕：提取音频并识别”。弹幕不是字幕，不会被当作正文导入。

### B 站音频快速/批量转录

选择“在线内容 → B 站 → 没有字幕”，每行粘贴一个完整 BV 链接（最多 10 个），选择可选登录浏览器并确认权限。VideoFlow 只向 yt-dlp 请求 `bestaudio`，不会在音频格式不可用时改下完整视频；每条临时音频在转录后删除。**只粘贴一个链接时**，字幕分段、可复制全文、可复制 SRT 和 TXT/SRT 下载会直接显示在页面底部；**粘贴多个链接时**，每个成功视频的 TXT/SRT 才会打包为 ZIP。最近使用的 Whisper 模型会被复用，因此批量任务不会重复加载模型。

### 西交 LMS 已授权回放快速转录

1. 打开 Edge 的 `edge://extensions` 或 Chrome 的 `chrome://extensions`，开启“开发人员模式”。
2. 点击“加载解压缩的扩展”，选择仓库中的 `D:\application\VideoFlow\browser-extension`。
3. 登录西交 LMS，进入具体学习活动页面，点击右下角“复制到 VideoFlow”。
4. 在 VideoFlow 的“在线内容 → 西交 LMS”页粘贴任务，确认权限后开始。

开始后先观察“正在提取课程音频（已处理 `00:xx:xx`）”；若媒体提供总时长，还会显示提取百分比。进入识别后，长课程会逐渐显示 `1/12`、`2/12` 等分块进度，60 分钟课程通常约有 12 块。

复制后应尽快开始，因为任务中的播放器授权会过期。若页面提示地址失效，回到仍可正常播放的课程活动页重新点击“复制到 VideoFlow”，不要反复提交旧任务。开始后不需要实时播放课程，也不要关闭启动 VideoFlow 的 PowerShell。

“提取课程音频”和“识别语音”是两个独立阶段。前者受校园网/CDN 和回放文件大小影响；如果平台只提供音视频复用文件，即使 VideoFlow 最终只保存音频，网络仍可能需要读取其中的视频数据。旧版在这一阶段只显示 0%；当前版会解析 FFmpeg 安全的时间进度，但不会显示、保存或回传签名播放地址。

浏览器助手的权限仅限 `https://lms.xjtu.edu.cn/*`。它不会导出 Cookie、账号或密码；复制内容包含一次性短期播放器 token，只应粘贴到本机 VideoFlow。应用处理后会清空输入框，不持久化 token、Bearer 授权或签名播放地址。V0.4.1 会优先使用 LMS 返回的授权直链，附带平台要求的同源请求头，并在失败时依次尝试备用地址和其他机位。若账号无观看权、任务过期、回放无音轨或使用 DRM，程序会停止并给出错误，不会尝试绕过。

### 只能在线播放的课程或网页视频

若以上快速方式失败，可选择“兼容录音”，确认你有权为个人学习记录当前内容，点击“开始录制电脑声音”。然后在已经登录的课程网页中**正常播放**回放；结束时回到 VideoFlow 点击“停止录制并转录”。程序会录制 Windows 当前默认扬声器正在播放的声音，转录后自动删除原始临时 WAV，只保留你选择下载的 TXT/SRT。

该兜底录音模式不会读取 LMS 链接、账号、Cookie、页面内容或视频流，也不会规避任何访问控制。录制时系统其他播放声音也会被一并录入；请关闭通知和其他音频，并确认 Windows 的默认输出设备正是正在播放课程的扬声器/耳机。

也可以命令行转录：

```powershell
.\.venv\Scripts\python.exe -m videoflow.cli "D:\\media\\lecture.mp4" --model base --language zh --output-dir exports
.\.venv\Scripts\python.exe -m videoflow.cli "D:\\media\\lecture.mp4" --profile balanced --language zh --prompt "课程术语" --output-dir exports
.\.venv\Scripts\python.exe -m videoflow.cli "D:\\media\\lecture.mp4" --profile gpu_turbo --language zh --prompt "高斯消去法，残值" --refine-low-confidence --output-dir exports
```

未传 `--language` 时自动识别语言。模型不可用、FFmpeg 无法解码或文件不是有效媒体时，程序会给出可读错误信息。完成后的诊断行会显示媒体时长和最后字幕位置；若二者相差过大，结果会标为需要检查，而不会直接宣称完整成功。

TXT 与 SRT 的用途不同：TXT 会合并模型的字幕片段并只在合理边界分自然段，不自行添加句号；SRT 继续保留每段时间码。

### 本机质量与速度基准

准备一段有权使用的 2–3 分钟代表性课程片段，以及与整段样本对应的人工参考稿：

```powershell
.\.venv\Scripts\python.exe -m videoflow.benchmark "D:\media\sample.mp4" --profiles fast,balanced,accurate --models base,small --language zh --reference "D:\media\reference.txt" --json benchmark.json
```

工具会报告加载时间、推理时间、RTF、峰值内存、最后字幕位置和 CER。没有人工参考稿时不会虚构准确率。测试媒体、参考稿和结果不要提交到 GitHub。

### 如何判断速度是否正常

[faster-whisper 官方基准](https://github.com/SYSTRAN/faster-whisper#benchmark)的 CPU 示例是在 i7-12700K、8 线程、`small/int8/beam 5` 上处理 13 分钟音频：普通管线约 102 秒（RTF 约 0.131），批量大小 8 时约 51 秒（RTF 约 0.065）。这只是特定硬件和音频的参考，不是所有电脑的承诺值。[CTranslate2 性能建议](https://opennmt.net/CTranslate2/performance.html)也建议 CPU 使用 INT8，并避免线程总数超过物理核心数。

本机 i7-14650HX 的当前实测如下；均未提供人工参考稿，因此只证明速度、内存和时间轴覆盖，不证明文字准确率：

| 测试 | 模式 | 推理时间 | RTF | 峰值内存 |
|---|---|---:|---:|---:|
| 5 分 56 秒授权中文视频 | GPU 增强 / turbo / beam 5 | 6.07 秒 | 0.017 | 约 1766 MB 进程内存 |
| 5 分 56 秒授权中文视频 | 快速 / base / beam 1 | 9.83 秒 | 0.028 | 约 964 MB |
| 5 分 56 秒授权中文视频 | 均衡 / base / beam 5 | 14.5 秒 | 0.041 | 本轮未单独记录 |
| 60 分钟连续有声重复样本 | 旧快速 / tiny（历史配置） | 60.66 秒 | 0.017 | 约 815 MB |
| 65 分钟稀疏语音样本 | 旧快速 / tiny（历史配置） | 14.26 秒 | 0.004 | 约 392 MB |

60 分钟样本由授权视频循环构造，用于施加连续语音负载，并非真实课程。实际耗时会随静音比例、音质、模型、散热和后台负载变化。对这台电脑，60 分钟课程的快速档若持续几十分钟且 CPU 几乎不活动，就不是正常速度；先停止旧进程、重启最新代码后重试，并观察进度是否按 `1/12` 到 `12/12` 推进。

## 测试

```powershell
.\.venv\Scripts\python.exe -m pytest
```

这些是无需下载模型或准备媒体的单元测试，覆盖自然段 TXT、SRT/ZIP、时间码、长媒体管线选择、覆盖诊断、CER、输入校验、转录结果转换、B 站字幕/音频命令、批量隔离、LMS 短期任务、同源请求头及备用地址重试。真实本地媒体和 B 站独立音频已经验收；LMS 修复后仍需由用户使用自己的登录态重新验收。

## 演示验证

在 Windows、Python 3.13、CPU INT8 环境中，VideoFlow 已用一段经授权的 5 分 56 秒中文 MP4 完成端到端验证：`tiny` 模型生成了 120 个带时间戳的分段，并成功生成 UTF-8 TXT 与标准 SRT。该结果用于验证流程可运行，不代表识别准确率基准；`tiny` 适合快速初稿，术语和同音字较多时建议改用 `base` 或 `small` 比较质量与处理时间。

V0.2 还验证了 B 站公开链接的无登录失败路径：平台未提供公开字幕时，应用在 45 秒内给出登录/本地文件回退说明，不下载视频。受登录权限影响，真实成功导入需在用户自己的已登录浏览器中完成。V0.3 将该类失败原因直接显示在“处理状态”中，便于区分未登录、无字幕、网络超时和 URL 格式错误。

V0.4 使用用户提供的 10 分 44 秒 B 站视频完成独立音频端到端验证：未读取 Cookie、未播放视频、未下载完整视频，仅获取约 11.8 MB 音频，`tiny` 模型生成 147 个中文分段。LMS 真实回放没有在开发环境中使用用户登录态测试，因此不能描述为已成功。

V0.4.1 在同一段经授权的 5 分 56 秒本地视频上验证批量推理和词级自动分段：快速档约 14.46 秒、48 段、1112 个字符；旧版 tiny 路径约 37.52 秒、1133 个字符，快速档约为 2.6 倍速度。均衡档在分段上限调整前约 33.02 秒、1087 个字符。最终自动分段会把每段限制在最多约 8 秒；字符数不等于准确率，术语质量仍应结合课程关键词和实际内容验收。

V0.4.2 的旧长媒体路径曾在一项真实 LMS 任务中运行超过 40 分钟后几乎不再消耗 CPU，因此不属于正常速度。修复后显式使用 8 个 CPU 线程，并把 20 分钟以上媒体改为 5 分钟重叠分块、块内批量识别。收到真实课程的低质量结果后，快速档改为 base/beam 1，并增加 GPU turbo 增强档；同一 356.33 秒视频在 RTX 4060 上为 6.07 秒、RTF 0.017，比 CPU balanced/base 的 14.5 秒更快。合成样本和无参考稿样本不能证明真实课程准确率，仍需人工抽查。

## 已知限制

- 目前没有说话人区分、字幕翻译或跨平台通用在线解析；批量队列仅支持最多 10 个 B 站 BV 链接。
- CPU 转录速度受电脑性能、批量大小和模型影响；高精度模式会明显更慢并使用更多内存。
- GPU 增强需要 NVIDIA CUDA 12、cuDNN 9 和足够的可用显存；首次使用还需下载 turbo 模型。当前只在 RTX 4060 Laptop 8 GB 上完成真实速度验证，不对更小显存作兼容承诺。
- 长媒体会切成带 3 秒上下文的 5 分钟块并顺序批量识别；块边界用时间中点去重，极少数跨边界长句仍可能出现不理想断句。页面显示的覆盖检查无法自动区分长尾静音与遗漏。
- 模型首次下载需要网络；之后可从本地缓存使用。
- LMS 播放接口可能随学校平台升级而变化；短期任务过期后需回课程页面重新复制。
